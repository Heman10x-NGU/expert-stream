HOW TO READ THIS
==============================================================================
  'coverage' is the fraction of rounds where the drafter could propose ANYTHING at all.
  It is the reason a genre can show 0.856 acceptance and still commit only 1.474 tokens
  per round: a suffix that has never been seen produces no draft, and that round commits
  exactly one token while still paying union(N) bytes.

  'tok/round' is the whole game. A round always reads union(N) experts. If it commits
  1.0 tokens, batching cost you extra bytes for nothing. The break-even tok/round is
  union(N)/6.00 - so N=2 needs 1.55 tokens per round, N=8 needs 3.58.

  A genre that clears it says nothing about a genre that does not. The spread IS the
  result: if only structured text clears the bar, then batching is a feature for
  code and data workloads and not for chat, and that is a design decision, not a bug.

  This does NOT prove the engine would get the win. It proves whether the tokens are
  obtainable for free. The batched execution path does not exist yet.
